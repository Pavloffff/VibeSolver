# Спецификация: модели рабочего пространства

## ADDED Requirements

### Требование: расширяемые подключения провайдеров

СИСТЕМА ДОЛЖНА предоставлять в рабочем пространстве каталог подключений моделей с поддержкой FreeToken, Ollama и OpenRouter. Подключения и операции провайдеров ДОЛЖНЫ разрешаться через расширяемый реестр; добавление нового провайдера НЕ ДОЛЖНО требовать изменения модели данных с закрытым перечислением типов.

#### Сценарий: подключить сервер FreeToken на хосте

- **ДАНО** пользователь находится на странице «Рабочее пространство / Модели»
- **КОГДА** он указывает доступный из бэкенда URL FreeToken и проверяет соединение
- **ТО** интерфейс показывает модели, опубликованные сервером, и сохраняет подключение без раскрытия секретного ключа в ответах API; запуск сервера и загрузка весов в VibeSolver не выполняются

### Требование: каталог моделей

СИСТЕМА ДОЛЖНА позволять синхронизировать доступные модели провайдера, добавлять модели в каталог рабочего пространства, показывать их провайдера, внешний ID, возможности и состояние, а также удалять модели. Повторная синхронизация НЕ ДОЛЖНА создавать дубликаты одной модели у того же подключения.

#### Сценарий: обновить список доступных моделей

- **ДАНО** провайдер подключён и доступен
- **КОГДА** пользователь синхронизирует каталог
- **ТО** интерфейс получает список по API провайдера и обновляет соответствующие записи рабочего пространства

### Требование: провайдер-специфичная загрузка модели

СИСТЕМА ДОЛЖНА различать загрузку весов и подключение модели из удалённого каталога. Для Ollama СИСТЕМА ДОЛЖНА позволять загрузить модель по введённому тегу из библиотеки Ollama через API Ollama с отображением состояния и прогресса. Для FreeToken СИСТЕМА ДОЛЖНА показывать модели, которые уже опубликованы запущенным сервером; СИСТЕМА НЕ ДОЛЖНА представлять синхронизацию этих моделей как скачивание весов. Для OpenRouter СИСТЕМА ДОЛЖНА добавлять cloud model ID из каталога без обещания локального скачивания весов.

#### Сценарий: загрузить модель в Ollama

- **ДАНО** пользователь ввёл тег модели из библиотеки Ollama
- **КОГДА** он запускает загрузку в подключённый экземпляр Ollama
- **ТО** UI показывает прогресс загрузки, затем помечает модель как локально доступную

#### Сценарий: подключить модель OpenRouter

- **ДАНО** OpenRouter вернул модель в каталоге
- **КОГДА** пользователь добавляет её в рабочее пространство
- **ТО** каталог сохраняет ссылку на удалённую модель без скачивания весов

### Требование: назначение моделей по возможностям

Каталог ДОЛЖЕН описывать возможности модели как расширяемые данные. Селектор индексации ДОЛЖЕН показывать только модели с подтверждённой возможностью embeddings; селектор генерации документации ДОЛЖЕН показывать только модели с подтверждённой возможностью chat/text generation.

#### Сценарий: выбрать модель для индексации

- **ДАНО** в каталоге есть chat-модели и embedding-модели
- **КОГДА** пользователь выбирает модель индексации проекта
- **ТО** список содержит только подходящие embedding-модели и показывает их размерность

#### Сценарий: выбрать модель для документации

- **ДАНО** для проекта доступна команда генерации документации из кода
- **КОГДА** пользователь открывает выбор модели генерации
- **ТО** список содержит только chat-модели, добавленные в каталог рабочего пространства

### Требование: безопасное хранение ключей

Секреты провайдеров ДОЛЖНЫ храниться на сервере в зашифрованном виде с ключом из конфигурации окружения. Секреты НЕ ДОЛЖНЫ возвращаться API, попадать в логи или сохраняться в браузерном постоянном хранилище. При обновлении подключения без ввода нового секрета существующий секрет ДОЛЖЕН сохраняться.

#### Сценарий: прочитать подключение

- **ДАНО** у подключения сохранён API-ключ
- **КОГДА** frontend получает настройки подключений
- **ТО** API возвращает только признак наличия ключа и безопасные поля конфигурации

### Требование: согласованность embedding-индекса

СИСТЕМА ДОЛЖНА сохранять идентификатор embedding-модели и размерность в метаданных индекса. Замена embedding-модели с несовместимой размерностью или пространством векторов НЕ ДОЛЖНА менять существующий индекс без переиндексации.

#### Сценарий: сменить модель индексации

- **ДАНО** индекс проекта построен другой embedding-моделью
- **КОГДА** пользователь выбирает новую модель
- **ТО** система предупреждает, что для применения требуется переиндексация, и не смешивает векторы разных моделей
