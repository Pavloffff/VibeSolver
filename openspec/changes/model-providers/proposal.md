# Предложение: подключение моделей рабочего пространства

## Проблема

В VibeSolver пока нет каталога моделей и настроек провайдеров. Выбор модели для индексации неактивен, а генерация документации не знает, через какую LLM работать. При этом Ollama, FreeToken и OpenRouter по-разному обнаруживают и загружают модели, поэтому одной кнопки «скачать модель» для всех провайдеров недостаточно.

## Решение

Добавить в рабочее пространство страницу «Модели», где пользователь подключает провайдеры, проверяет соединение, синхронизирует каталог и добавляет нужные модели. Реестр провайдеров должен быть расширяемым.

- **FreeToken:** подключаться к уже работающему серверу на хосте и импортировать только опубликованные им модели (например, `gpt-oss-20b` или `qwen-35b`). Пользователю достаточно такого подключения; запуск FreeToken и управление загрузкой его весов из VibeSolver не нужны.
- **Ollama:** подключаться к серверу, показывать установленные модели и позволять загрузить модель по её тегу из библиотеки Ollama с отображением прогресса.
- **OpenRouter:** подключаться по API-ключу, показывать каталоги chat- и embedding-моделей и добавлять выбранные записи в рабочее пространство. Веса модели локально не скачиваются.

Каталог различает возможности моделей: генерация текста (chat) и построение эмбеддингов (embedding). В индексации проекта показываются только модели с embedding-возможностью; для генерации документации появляется выбор chat-модели. Параметры выбранных моделей и подключений хранятся на сервере рабочего пространства.

## Границы первой реализации

- Управление провайдерами и моделями, проверка соединения, синхронизация/загрузка для Ollama и выбор модели для задач.
- Реальная индексация, генерация документации и запуск моделей FreeToken из интерфейса не входят в первую реализацию, если пользователь отдельно не расширит объём.
- Модель FreeToken загружается и запускается вне VibeSolver. Интеграция подключается к уже работающему серверу и показывает опубликованные им модели. Изменение процесса FreeToken и управление его весами через UI исключены из объёма.
- Реальный API-ключ OpenRouter нужен для запросов. Секрет нельзя возвращать через API или хранить открытым текстом.
- Confluence, другие облачные шлюзы и загрузка произвольных весов/файлов моделей вне поддерживаемых API не входят в первую реализацию.

## Предпосылки

- Модели и подключения принадлежат экземпляру VibeSolver, а не отдельному пользователю: сейчас в продукте нет авторизации пользователей.
- API провайдера вызывается бэкендом. Настроенный адрес должен быть доступен из процесса API, в том числе из Docker.
- Переключение embedding-модели у уже созданного индекса потребует переиндексации: в одном индексе нельзя без проверки смешивать векторы разной размерности и пространства представлений.
