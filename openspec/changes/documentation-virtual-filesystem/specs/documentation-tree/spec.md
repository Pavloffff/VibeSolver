# Спецификация: дерево документации проекта

## Добавленные требования

### Требование: расширяемое файловое пространство документации

СИСТЕМА ДОЛЖНА предоставлять документацию проекта как абстрактное файловое пространство с относительными иерархическими путями, стабильными идентификаторами файлов и отделённым от метаданных хранилищем содержимого. Список типов источников ДОЛЖЕН расширяться через реестр адаптеров, без закрытого перечня типов в схеме хранения.

#### Сценарий: показать вложенные каталоги

- **ДАНО** документация содержит `guide/setup.md` и `api/readme.md`
- **КОГДА** пользователь открывает блок документации
- **ТО** система показывает каталоги и файлы в виде дерева, а раскрытие/сворачивание каталога управляет видимостью его потомков

#### Сценарий: сохранить существующие материалы

- **ДАНО** проект содержит материалы документации прежнего плоского формата
- **КОГДА** проект открывается после обновления
- **ТО** материалы доступны в локальном корне дерева с прежними именами и содержимым

### Требование: добавление файла и архива в выбранную папку

СИСТЕМА ДОЛЖНА позволять добавлять файл или архив из корня и из любой папки дерева. Файл ДОЛЖЕН попадать непосредственно в выбранную папку под исходным именем. Архив ZIP, TAR или TAR.GZ ДОЛЖЕН безопасно распаковываться в дочернюю папку с именем архива без расширения и сохранять внутреннюю структуру. Распаковка ДОЛЖНА отклонять небезопасные пути и специальные файлы и соблюдать настраиваемый лимит распакованного размера.

#### Сценарий: загрузить файл в папку

- **ДАНО** выбрана папка `guide`
- **КОГДА** пользователь добавляет файл `setup.md`
- **ТО** файл появляется по пути `guide/setup.md`

#### Сценарий: распаковать архив

- **ДАНО** выбрана корневая папка и загружается `api-docs.tar.gz` с файлом `v1/openapi.md`
- **КОГДА** архив успешно проверен и распакован
- **ТО** дерево содержит `api-docs/v1/openapi.md`

### Требование: разрешение конфликтов файлов

При совпадении нормализованного пути СИСТЕМА ДОЛЖНА сравнить содержимое. Идентичное содержимое ДОЛЖНО быть дедуплицировано. Различающиеся текстовые версии ДОЛЖНЫ быть представлены пользователю в интерфейсе сравнения с выбором существующей версии, входящей версии или редактируемого результата слияния. Автоматический diff3 допускается только при наличии общей базовой версии и отсутствии конфликтующих изменений. Бинарный конфликт ДОЛЖЕН требовать явного выбора версии. Источник входящей версии ДОЛЖЕН оставаться доступен до завершения выбора.

#### Сценарий: одинаковый файл добавлен повторно

- **ДАНО** путь занят файлом с тем же содержимым
- **КОГДА** пользователь добавляет этот файл снова
- **ТО** второй экземпляр не создаётся и система сообщает, что содержимое уже присутствует

#### Сценарий: текстовые версии различаются

- **ДАНО** входящий текстовый файл совпадает по пути, но отличается от существующего и общей базы нет
- **КОГДА** пользователь подтверждает добавление
- **ТО** система показывает сравнение обеих версий и предлагает выбрать одну или вручную отредактировать объединённый результат до записи

### Требование: внешние источники в зарезервированных каталогах

Адаптер внешнего источника ДОЛЖЕН монтировать свои материалы в выделенный корневой каталог, например `Confluence/` или `GitHub Wiki/`. Имена таких каталогов ДОЛЖНЫ резервироваться без учёта регистра, а локальные загрузки и генераторы НЕ ДОЛЖНЫ создавать или записывать в них. Синхронизация ДОЛЖНА сохранять происхождение узлов и изменять только область соответствующего адаптера.

#### Сценарий: подключить источник Confluence

- **ДАНО** зарегистрирован адаптер Confluence
- **КОГДА** он импортирует страницы проекта
- **ТО** страницы доступны под `Confluence/`, а узлы помечены происхождением Confluence

#### Сценарий: запретить занятое имя

- **ДАНО** `Confluence/` зарезервирован подключённым типом источника
- **КОГДА** пользователь или генератор пытается создать локальную папку `Confluence`
- **ТО** операция отклоняется с понятным сообщением

### Требование: добавление из папки дерева

Каждый узел-каталог ДОЛЖЕН предоставлять действие добавления файла или архива. Действие ДОЛЖНО передавать выбранный каталог общей операции загрузки, не меняя путь существующих узлов.

#### Сценарий: добавить файл из вложенного каталога

- **ДАНО** раскрыта папка `manuals/install`
- **КОГДА** пользователь выбирает действие `+` и файл `linux.md`
- **ТО** новый файл предлагается по пути `manuals/install/linux.md`

### Требование: генерация документации в локальную область

Генератор документации из кода ДОЛЖЕН возвращать расширяемый набор файлов и каталогов с относительными путями, а не один обязательный Markdown-файл. Результат ДОЛЖЕН записываться только в локальную область виртуальной файловой системы через общий механизм добавления и разрешения конфликтов; он НЕ ДОЛЖЕН изменять или удалять узлы внешних источников. Генератор ДОЛЖЕН отклонять абсолютные и выходящие за корень пути.

#### Сценарий: генератор создаёт вложенные файлы

- **ДАНО** генератор возвращает `README.md` и `architecture/components.md`
- **КОГДА** результат сохранён
- **ТО** дерево содержит оба файла и каталог `architecture` в локальной области

#### Сценарий: генератор не может писать в Confluence

- **ДАНО** подключён каталог `Confluence/`
- **КОГДА** генератор возвращает файл с путём `Confluence/summary.md`
- **ТО** система отклоняет этот путь и не меняет данные Confluence
