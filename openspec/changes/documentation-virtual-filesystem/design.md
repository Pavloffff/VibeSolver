# Проектирование виртуальной файловой системы документации

## Модель

Ввести пространство `documentation` с узлами, адресуемыми нормализованными относительными POSIX-путями. Метаданные узла отделены от байтов содержимого; каталоги могут быть виртуальными (выводятся из путей), а файлы имеют стабильный ID, имя/путь, MIME или признак текстового содержимого, происхождение и версию. Старые ресурсы документации мигрируют в эту модель без потери содержимого. User Flow остаётся в существующей модели ресурсов.

Точки хранения содержимого скрыты за файловым портом (read/write/list/mkdir/delete/merge), реализованным адаптером хранилища. API и UI работают с абстрактными путями и операциями, а не с S3-ключами. Коннекторы источников регистрируются по ключу и возвращают manifest файлов с корневым каталогом и идентичностью происхождения; добавление типа источника не требует изменения закрытого перечня в схеме БД.

## Загрузка и конфликты

- Одиночный файл адресуется в выбранную папку под собственным именем.
- Архивы ZIP/TAR/TAR.GZ безопасно распаковываются в `<имя архива>/<содержимое>`. Запрещены абсолютные пути, `..`, ссылки наружу, специальные файлы и превышение лимита распаковки.
- Пути нормализуются; запрещены пустые сегменты, `.`/`..`, разделители внутри имени и зарезервированные папки внешних источников в корне локальной области.
- При точном совпадении хеша существующий файл сохраняется без дубля.
- При совпадении пути с разным содержимым создаётся задача разрешения конфликта с обеими версиями и общим предком, если он известен. Текстовый diff3 применяется только при наличии достоверной общей базы и отсутствии пересекающихся изменений. Во всех остальных случаях показывается поблочное сравнение и пользователь выбирает вариант или редактирует объединённый черновик. Бинарные файлы заменяются только после явного выбора.

## Источники и происхождение

Локальная область включает ручные загрузки и результат генерации. Области внешних адаптеров монтируются в зарезервированные корневые каталоги (`Confluence/`, `GitHub Wiki/`); удалённые узлы обновляются/удаляются только синхронизацией соответствующего адаптера. Внешние файлы не перезаписывают локальные; конфликт одинаковых виртуальных путей показывается как отдельные варианты происхождения. Registry адаптеров описывает ключ, отображаемое имя, корневой каталог и операции синхронизации.

## Генерация

Контракт генератора документации возвращает manifest: один или несколько относительных путей, текстовое содержимое и допустимые каталоги. Запуск ограничивает запись локальной областью. Результат добавляется через общий механизм импорта и разрешения конфликтов. Генератор не получает write-доступ к областям внешних адаптеров.

## Интерфейс

Дерево строится из manifest узлов и раскрывается/сворачивается. У каждой папки есть действие `+` с вариантами добавления файла или архива. После добавления пути с конфликтами UI показывает сравнение и выбор для каждого конфликта; каталог архива раскрывается как обычная папка. Текущий просмотрщик/редактор Markdown открывает файл по виртуальному пути.

## Миграция и совместимость

Существующие `resources.documentation` должны быть импортированы в локальную область, сохранив ID, имя, содержимое и происхождение. До завершения миграции чтение старого формата поддерживается либо миграция выполняется атомарно при записи. `resources.user_flow` остаётся нетронутым. Обновление контракта HTTP требует переэкспорта `backend/api/openapi.json` и `.yaml`.
