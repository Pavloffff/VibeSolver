# Предложение: опциональный веб-поиск для обращений

## Проблема

Внутренние индексы кода, документации, user flow и логов не всегда содержат ответ на ошибку внешней библиотеки, операционной системы или сервиса. В таких случаях обращению могут помочь актуальные официальные источники, но отправлять сырые логи или включать интернет-поиск без явного согласия нельзя.

## Изменение

Добавить настройку поискового провайдера проекта с первой реализацией через SearXNG и отдельную галочку веб-поиска у обращения. Галочка по умолчанию выключена. Когда она включена, внешний поиск запускается только после внутреннего RAG и только если данных недостаточно. Поисковый запрос строится из очищенной сигнатуры ошибки, названия компонента и версий; архивы, полные log lines, токены, персональные данные и полный текст обращения наружу не отправляются.

Результаты веб-поиска добавляются в dossier как отдельные недоверенные источники с URL-цитатами. Они дополняют внутренние доказательства и не заменяют их.

## Границы

- Веб-поиск выключен по умолчанию и явно включается для каждого обращения.
- SearXNG подключается через расширяемый интерфейс провайдера.
- MCP не обязателен для первого релиза; отдельный MCP-адаптер можно добавить, если появятся несколько внешних инструментов.
- Автоматическая отправка исходных логов и ticket description во внешний поисковик запрещена.
