# Проектирование статистики индексов

## Выбранный подход

Использовать уже доступные данные: `ProjectStats.file_count`, ресурсы `documentation`/`user_flow` в конфигурации проекта и `ProjectIndexRun.files_total/chunks_total`. Не добавлять новый endpoint или агрегированные таблицы: количества запуска уже хранятся вместе с результатом индексации, а количество локальных ресурсов уже загружено для дерева документации.

В UI разделить сводные количества ресурсов и сводку по каждому индексу. Для ещё не запущенного индекса отображать отсутствие результата. Состояние актуальности остаётся в отдельном блоке индексации и не дублируется как второе независимое состояние.

## Ограничения первой версии

- `files_total` — число файлов снимка, переданных обработчику; бинарные или неподдерживаемые файлы могут не дать фрагментов.
- `chunks_total` — поисковые фрагменты, пригодные для retrieval; для User Flow это может быть количество сценариев JSON или текстовых фрагментов.
- Число локальных документов/сценариев означает элементы дерева ресурсов, а не число файлов внутри сжатого архива, если архив хранится одним ресурсом.
- Распределение по языкам, разделам, форматам и диагностикам потребует отдельного расширения API и не входит в эту итерацию.
