# Требования: генерация материалов по индексам

## ADDED Requirements

### Requirement: Генерация документации по коду

Система ДОЛЖНА генерировать документацию по актуальному индексу кода проекта и учитывать существующие локальные текстовые документы. Актуальный индекс кода обязателен; индекс документации необязателен, но при его актуальности также участвует в поиске. Генератор ДОЛЖЕН искать по нескольким аспектам поведения, включая пользовательские сценарии, бизнес-правила, данные, интеграции, ошибки и тесты. Существующие файлы нельзя перезаписывать: новый файл с занятым именем сохраняется рядом под свободным именем.

#### Scenario: Кодовый индекс актуален

- ДАНО завершённый индекс кода, соответствующий текущему снимку проекта
- И локальные документы уже существуют, независимо от того, завершена ли их индексация
- КОГДА пользователь запускает генерацию документации
- ТОГДА генератор ищет релевантные фрагменты кода по нескольким аспектам функциональности, добавляет найденные существующие локальные документы в контекст и создаёт дополняющие файлы в соответствующих папках

#### Scenario: Имя создаваемого файла уже занято

- ДАНО сгенерированный путь уже занят существующим локальным файлом
- КОГДА генератор сохраняет новый файл
- ТОГДА он выбирает свободное имя в той же папке и не перезаписывает существующее содержимое

#### Scenario: Кодовый индекс отсутствует или устарел

- ДАНО индекс кода не завершён или не соответствует текущему снимку
- КОГДА пользователь пытается запустить генерацию документации
- ТОГДА генератор не запускается и сообщает, что требуется актуальная индексация кода

### Requirement: Генерация User Flow по коду и документации

Система ДОЛЖНА генерировать User Flow, используя актуальные индексы кода и документации одновременно. Генерация ДОЛЖНА быть недоступна, если любой из этих индексов отсутствует или устарел.

#### Scenario: Оба индекса актуальны

- ДАНО актуальные завершённые индексы кода и документации
- КОГДА пользователь запускает генерацию User Flow
- ТОГДА генератор извлекает контекст отдельно из обоих индексов и формирует черновики сценариев

#### Scenario: Один индекс не готов

- ДАНО кодовый или документационный индекс отсутствует, завершился ошибкой либо устарел
- КОГДА пользователь запускает генерацию User Flow
- ТОГДА генератор не запускается и указывает, какой индекс нужно подготовить

#### Scenario: Модель вернула распространённую альтернативную форму сценария

- ДАНО модель вернула JSON-массив сценариев или поля-синонимы `actions`, `expected` либо `outcome`
- КОГДА генератор проверяет черновик User Flow
- ТОГДА он преобразует их в каноническую схему, оставляет `approved=false` и сохраняет файл

#### Scenario: User Flow нельзя восстановить

- ДАНО после одной попытки исправления в сценарии всё ещё нет обязательного действия или ожидаемого результата
- КОГДА генератор проверяет ответ
- ТОГДА API возвращает ошибку ответа модели, а не ошибку конфликта состояния индекса

### Requirement: Локальное сохранение и проверяемое происхождение

Система ДОЛЖНА сохранять сгенерированную документацию и User Flow в локальные ресурсы соответствующей категории, включая вложенные пути и новые папки. Система НЕ ДОЛЖНА записывать результат генерации в Confluence или другой внешний источник. Генерируемый материал ДОЛЖЕН содержать ссылки на подтверждающие исходные пути/разделы и идентификаторы использованных версий индексов.

#### Scenario: Создание вложенных файлов

- ДАНО генератор сформировал несколько файлов с вложенными путями
- КОГДА пользователь сохраняет результат
- ТОГДА система создаёт недостающие папки и файлы внутри локального дерева соответствующей категории

#### Scenario: Сгенерированный путь уже занят

- ДАНО в локальном дереве уже есть файл с тем же путём, но другим содержимым
- КОГДА генератор сохраняет результат
- ТОГДА система выбирает свободное имя рядом с исходным путём и не перезаписывает файл

#### Scenario: Проверка источников

- ДАНО результат содержит фактические сведения о коде или пользовательском поведении
- КОГДА результат сохранён
- ТОГДА пользователь может перейти к указанным путям и определить версии индексов, использованные генератором

### Requirement: Человек утверждает User Flow

Система ДОЛЖНА сохранять сгенерированные сценарии как черновики и НЕ ДОЛЖНА включать их в актуальный индекс User Flow до явного подтверждения человеком.

#### Scenario: Черновик создан

- ДАНО генератор сформировал сценарий
- КОГДА сценарий сохранён в проекте
- ТОГДА он отображается как неутверждённый и не индексируется как утверждённый User Flow

#### Scenario: Черновик утверждён

- ДАНО пользователь проверил черновик и подтвердил его
- КОГДА подтверждение сохранено
- ТОГДА индекс User Flow становится устаревшим и может быть построен заново по утверждённым сценариям

### Requirement: Выбор чат-модели для генерации

Система ДОЛЖНА разрешать выбирать любую добавленную чат-модель поддерживаемого провайдера для генерации по индексам кода и документации. При использовании удалённого провайдера система ДОЛЖНА отправлять только релевантные найденные фрагменты, не весь индекс и не секреты проекта.

#### Scenario: Выбрана чат-модель

- ДАНО для генерации выбрана добавленная в рабочее пространство чат-модель
- КОГДА генератор формирует запрос
- ТОГДА релевантные фрагменты индексов передаются выбранному провайдеру в пределах лимита контекста

#### Scenario: Выбранная модель не поддерживает чат

- ДАНО выбранная модель не имеет capability `chat`
- КОГДА пользователь запускает генерацию по коду или документации
- ТОГДА система блокирует запрос и предлагает выбрать чат-модель
