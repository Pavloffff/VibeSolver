# Дизайн: карточка проекта и автоматический импорт

## Модель

Корневая запись `sources` остаётся проектом и содержит подключение исходного кода. В её JSONB `config.resources` хранится расширяемое отображение категории ресурса в списки `{type, name, config}`. Текущая реализация добавляет `type=archive` и `config.upload_key` для категорий `documentation` и `user_flow`. Ключи категорий не фиксируются ограничением БД, чтобы позже добавить Confluence и Wiki.

## Поток создания и повторного импорта

Веб-форма создаёт источник, ставит его импорт в очередь и открывает страницу проекта. Страница опрашивает существующий endpoint статуса импорта. Если очередь недоступна после успешного создания источника, проект всё равно открывается и показывает ошибку с возможностью повторить запуск.

Редактирование использует `PATCH /api/v1/sources/{id}`. Конфигурация коннектора частично объединяется с текущей, чтобы скрытые секретные поля (например, `token_ref`) не терялись. Валидатор коннектора проверяет результат до сохранения. После успешного сохранения UI запускает новый импорт.

Новые read endpoints возвращают одну запись источника и агрегированное количество импортированных файлов. Контракт экспортируется в оба OpenAPI-файла.

## Интерфейс проекта

- Верхняя панель: хлебные крошки «Рабочее пространство / Проекты / имя проекта»; крошка рабочего пространства ведёт к списку. На странице проекта остаётся ссылка на GitHub, если URL репозитория ведёт на `github.com`.
- Список проектов: вся строка проекта открывает его страницу; в действиях доступны изменение и удаление. Изменение использует общую форму и автоматически повторяет импорт.
- Блок импорта: состояние, ошибка, прогресс и повторный запуск при сбое.
- Блок контекста: добавление документации и User Flow как архивов; существующие прикреплённые архивы отображаются списком.
- Блок индексации: селектор модели-заглушки и действие индексации. Действие заблокировано без документации и User Flow; при наличии показывает локализованное сообщение-заглушку и не имитирует выполнение.
- Блок статистики: только количество импортированных файлов. Метрики обращений пока не показываются.
- Секции страницы проекта идут в одну колонку. При добавлении документации или User Flow отображается поле «Тип источника» с единственным текущим вариантом «Архив»; отдельное имя ресурса не запрашивается, в списке используется имя файла.
- Обращения: отдельная страница проекта с собственным состоянием интерфейса, переходом из шапки проекта и хлебными крошками до проекта. Заглушка не создаёт фиктивных записей; отдельное хранение списка будет подключено вместе с реализацией обращений.

## Безопасность и ошибки

- При изменении конфигурации сохранять существующие ключи, если клиент их не передал; не возвращать `token_ref` в API.
- Архивы загружаются существующим endpoint загрузки, ограничения размера и проверка формата остаются в силе.
- Ошибка постановки задачи не должна скрывать успешно созданный проект.
- Отображать ошибки импорта как текст статуса, без traceback.
