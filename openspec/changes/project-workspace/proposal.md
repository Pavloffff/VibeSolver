# Предложение: карточка проекта и автоматический импорт

## Зачем

Сейчас проект представлен источником в общем списке, а импорт запускается отдельной кнопкой. Пользователю нужен единый поток: создать проект и сразу увидеть результат импорта, открыть его детали, прикрепить документацию и User Flow, а после ошибки исправить конфигурацию и повторить импорт.

## Решение

- Считать текущую запись исходного кода проектом на этом этапе. Отдельные таблицы проектов не добавлять.
- После создания источника сразу ставить его импорт в очередь и открывать страницу проекта.
- Разрешить прикреплять к проекту архивы документации и User Flow. Хранить их тип и ключ загрузки в расширяемом объекте ресурсов в конфигурации проекта. Позже ресурсы смогут ссылаться на Confluence и Wiki.
- Добавить страницу проекта со статусом и прогрессом импорта, количеством файлов, ссылкой на GitHub для GitHub-репозиториев, формами добавления ресурсов, заглушкой модели индексации и заглушкой добавления обращения.
- Оставить изменение проекта в списке проектов. На странице проекта не показывать действие редактирования; после ошибки оставить повторный запуск импорта.
- В списке проектов сделать всю строку интерактивной, а в колонке «Действия» дать редактировать проект тем же потоком, что и на его странице.
- Уточнить breadcrumb до «Рабочее пространство / Проекты / имя проекта» и сделать «Рабочее пространство» переходом к списку проектов.
- Расположить секции страницы проекта в одну колонку; в статистике пока показывать только количество файлов.
- При добавлении документации и User Flow показывать тип источника (сейчас — архив) без отдельного поля названия.
- Вынести обращения в отдельный экран проекта с собственным состоянием и переходом из шапки проекта.
- Индексация пока не выполняется: модель отображается как заглушка, действие индексации доступно только при наличии документации или User Flow и сообщает, что функция появится позже.

## Границы

- Текущие типы вложений — только архивы `.zip` и `.tar.gz`.
- Подключения Confluence/Wiki и реальные issue, метрики, embeddings и индексатор остаются будущими возможностями.
- Существующий API списка источников сохраняется; пользовательский интерфейс называет их проектами.
