# Спецификация: рабочее пространство проекта

## Добавленные требования

### Требование: автоматический импорт при создании проекта

После успешного создания проекта интерфейс ДОЛЖЕН автоматически поставить импорт исходного кода в очередь и открыть страницу созданного проекта. Отдельное действие «Импорт» в общем списке проектов НЕ ДОЛЖНО отображаться.

#### Сценарий: создание проекта запускает импорт

- **ДАНО** пользователь заполнил валидную форму подключения репозитория или архива
- **КОГДА** пользователь нажимает «Создать проект»
- **ТО** проект создаётся, задача импорта автоматически ставится в очередь и открывается страница проекта

#### Сценарий: очередь импорта недоступна

- **ДАНО** источник проекта успешно сохранён, но очередь задач недоступна
- **КОГДА** UI пытается начать импорт
- **ТО** страница проекта всё равно открывается с понятной ошибкой и действием повтора

### Требование: страница проекта

СИСТЕМА ДОЛЖНА открывать страницу проекта при выборе проекта в списке. Страница ДОЛЖНА показывать статус импорта, прогресс, число импортированных файлов, доступные ресурсы контекста, секцию индексации и секцию обращений. Основные секции страницы ДОЛЖНЫ располагаться в одну колонку. Статистика на данном этапе ДОЛЖНА содержать только число файлов.

#### Сценарий: переход к деталям

- **ДАНО** проект присутствует в списке
- **КОГДА** пользователь выбирает любую часть его строки
- **ТО** UI открывает страницу проекта с текущим статусом импорта и числом файлов

#### Сценарий: ссылка на GitHub

- **ДАНО** конфигурация проекта содержит URL репозитория на `github.com`
- **КОГДА** отображается страница проекта
- **ТО** пользователю доступна ссылка на репозиторий GitHub

### Требование: архивы документации и User Flow

СИСТЕМА ДОЛЖНА позволять прикрепить к проекту архив документации и архив User Flow. Форма добавления ДОЛЖНА показывать тип источника и НЕ ДОЛЖНА запрашивать отдельное название ресурса. Категории ресурсов ДОЛЖНЫ храниться расширяемо, без перечисления категорий в схеме базы данных. Текущие вложения — `.zip` и `.tar.gz`; модель допускает последующие источники Confluence и Wiki.

#### Сценарий: добавить документацию

- **ДАНО** открыта страница проекта
- **КОГДА** пользователь загружает архив через действие «Добавить документацию»
- **ТО** ключ архива сохраняется в ресурсах документации проекта и отображается в списке
- **И** пользователь видит текущий тип источника «Архив» без поля названия

#### Сценарий: добавить User Flow

- **ДАНО** открыта страница проекта
- **КОГДА** пользователь загружает архив через действие «Добавить описание User Flow»
- **ТО** ключ архива сохраняется в ресурсах User Flow проекта и отображается в списке
- **И** пользователь видит текущий тип источника «Архив» без поля названия

### Требование: навигация и действия в списке проектов

СИСТЕМА ДОЛЖНА отображать breadcrumb проекта как «Рабочее пространство / Проекты / имя проекта». Крошка «Рабочее пространство» ДОЛЖНА возвращать к списку проектов. В списке проектов вся строка ДОЛЖНА открывать проект, а колонка «Действия» ДОЛЖНА содержать изменение и удаление. Изменение ДОЛЖНО запускать повторный импорт по тому же потоку, что и форма на странице проекта.

#### Сценарий: вернуться к списку проектов

- **ДАНО** открыта страница проекта
- **КОГДА** пользователь нажимает крошку «Рабочее пространство»
- **ТО** открывается список проектов

### Требование: заглушка индексации

Страница проекта ДОЛЖНА показывать выбор модели как неактивную заглушку. Действие индексации ДОЛЖНО быть заблокировано, пока проект не содержит документацию или User Flow. До появления индексатора система НЕ ДОЛЖНА показывать фиктивный прогресс или результат индексации.

#### Сценарий: нет контекста для индексации

- **ДАНО** к проекту не добавлена документация и не добавлен User Flow
- **КОГДА** пользователь открывает проект
- **ТО** действие индексации неактивно

#### Сценарий: индексатор пока не реализован

- **ДАНО** к проекту добавлена документация или User Flow
- **КОГДА** пользователь нажимает доступное действие индексации
- **ТО** система сообщает, что индексация появится позже, и не показывает фиктивное выполнение

### Требование: исправление проекта после ошибки

При ошибке импорта страница проекта ДОЛЖНА показывать действие «Изменить проект». Сохранение исправленных имени или параметров коннектора ДОЛЖНО валидировать конфигурацию и автоматически ставить новый импорт в очередь.

#### Сценарий: исправить конфигурацию и повторить импорт

- **ДАНО** последний импорт проекта завершился ошибкой
- **КОГДА** пользователь исправляет конфигурацию и сохраняет изменения
- **ТО** проект обновляется, новый импорт ставится в очередь, UI показывает его прогресс

### Требование: заглушка обращений

Страница проекта ДОЛЖНА отображать секцию обращений и кнопку добавления обращения. До реализации обработки обращений интерфейс ДОЛЖЕН обозначать добавление как будущую возможность и НЕ ДОЛЖЕН создавать фиктивные обращения или метрики.

#### Сценарий: открыть секцию обращений

- **ДАНО** открыта страница проекта без подключённых обращений
- **КОГДА** пользователь просматривает секцию обращений
- **ТО** отображаются заглушки добавления обращения и метрик
