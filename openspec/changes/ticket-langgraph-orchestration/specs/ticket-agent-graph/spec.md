# Ticket-agent graph

## ADDED Requirements

### Requirement: Явная LangGraph-оркестрация обращения

Система ДОЛЖНА исполнять текущий конвейер обращения как скомпилированный LangGraph StateGraph с типизированным состоянием и явными узлами разрешения моделей, триажа, retrieval, решения и завершения. Граф ДОЛЖЕН сохранять существующие API и бизнес-результаты.

#### Scenario: Успешный ответ

- ДАНО: модели доступны, retrieval вернул evidence, resolver ответил с валидными source refs
- КОГДА: выполняется граф обращения
- ТОГДА: узлы идут в порядке разрешения моделей, триажа, исследования, решения и ответа, а обращение получает статус answered

#### Scenario: Пустое досье

- ДАНО: retrieval не вернул evidence
- КОГДА: завершается узел исследования
- ТОГДА: условный переход направляет граф к эскалации без вызова resolver

#### Scenario: Невалидные citations

- ДАНО: resolver предлагает ответ, но не ссылается ни на один переданный evidence ref
- КОГДА: узел проверки результата маршрутизирует граф
- ТОГДА: граф завершает обращение эскалацией с существующей причиной о невалидных ссылках

#### Scenario: Ошибка выполнения графа

- ДАНО: узел графа выбрасывает ошибку после начала обработки
- КОГДА: `run` обрабатывает исключение
- ТОГДА: ticket получает статус failed и ошибку в поле эскалации, как и до миграции

### Requirement: Trace шагов графа

Каждый шаг, который вызывает LLM или retrieval, ДОЛЖЕН добавлять append-only запись в `ticket_steps` с теми же названиями шагов, результатами, использованием модели, длительностью, токенами и стоимостью, что и до миграции.

#### Scenario: Trace при успешном запуске

- ДАНО: граф успешно завершил разбор
- КОГДА: клиент получает детали обращения
- ТОГДА: trace содержит triage, investigate и resolve в прежнем порядке и с прежними структурами данных

### Requirement: Безопасные границы графа

Граф ДОЛЖЕН иметь явное ограничение глубины исполнения и НЕ ДОЛЖЕН выполнять код проекта или запускать тесты. Долговременное состояние графа в этой фазе НЕ сохраняется в LangGraph checkpointer.

#### Scenario: Граф не запускает код

- ДАНО: ticket содержит запрос на исправление или текст лога
- КОГДА: ticket-agent выполняет текущий граф
- ТОГДА: он только анализирует текст и RAG evidence и не вызывает shell, sandbox или тестовый runner
