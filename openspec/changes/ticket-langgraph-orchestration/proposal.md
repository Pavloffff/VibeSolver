# Предложение: оркестрация обращений через LangGraph

## Проблема

Текущий конвейер обращения выполняется последовательным методом Python. У него уже есть условные исходы, но связи между триажем, retrieval и решением не представлены явным графом, поэтому расширять его новыми узлами и ветками неудобно.

## Изменение

Перевести существующий поток на LangGraph: разрешение моделей → триаж → retrieval dossier → ответ либо эскалация. Явно выразить ветки пустого dossier, ответа без валидных citations и решения модели об эскалации. Сохранить существующие API, статусы, модели, промпты, ticket-scoped RAG и append-only трассу шагов.

## Границы

- Изменение не добавляет автоматическое исправление кода, запуск тестов, песочницу, human approval или MR builder.
- LangGraph исполняет только существующие шаги и не запускает код проекта.
- В этой фазе не включается долговременный checkpointer: run остаётся синхронным HTTP use case, а аудит шагов хранится в `ticket_steps`.
- Поток остаётся без циклов; лимит рекурсии графа задаётся явно как защита от ошибочной топологии.
