## MODIFIED Requirements

### Requirement: Единый просмотр материалов

Система ДОЛЖНА открывать код, документацию и пользовательские сценарии в общем полноэкранном окне с деревом и областью чтения. Просмотр использует всю ширину и высоту окна приложения. Исходный код открывается только для чтения с подсветкой языка.

#### Scenario: Проверка реализации

- ДАНО импортированный снимок проекта
- КОГДА инженер выбирает файл в исходном коде
- ТО инженер видит содержимое в контексте дерева, ветки и снимка.

#### Scenario: Выход из рабочей области

- ДАНО инженер открыл файл из обзора и отредактировал его
- КОГДА инженер нажимает Esc или кнопку закрытия
- ТО фокус возвращается к элементу, открывшему рабочую область, а выбранный файл и черновик доступны при повторном открытии.

### Requirement: Создание и уточнение обращения

Система ДОЛЖНА постоянно показывать кнопку создания. Она открывает полноразмерную форму с выбором заполнения вручную, из TXT или ZIP с одним текстом обращения. На телефоне форма использует экран целиком. Архивы журналов можно добавить сразу и перед повторным разбором. Комментарий повторного разбора и предыдущий результат ДОЛЖНЫ учитываться в новом запуске. Выбранный профиль действует на один запуск.

#### Scenario: Повторный анализ

- ДАНО завершённый разбор
- КОГДА инженер открывает материалы для повторного запуска
- ТО поле комментария и выбор архива расположены рядом. На узком экране комментарий идёт первым, выбор архива следует за ним. Уже прикреплённые архивы перечислены ниже.

#### Scenario: Уточнение причины по новым журналам

- ДАНО завершённый разбор
- КОГДА инженер дополняет его комментарием и новыми журналами
- ТО обработка учитывает готовность журналов, сохраняет историю и показывает предложение и открытый журнал с возможностью копирования.

### Requirement: Размещение настроек

Разрешение внешнего поиска ДОЛЖНО управляться в настройках графа. Наблюдение интерфейса ДОЛЖНО находиться в экспериментальном разделе с явным выбором обращения. Основная навигация проекта ведёт к обращениям и графу.

#### Scenario: Новый проект

- ДАНО проект с настройками по умолчанию
- КОГДА инженер открывает обращения
- ТО внешняя передача выключена, сбор наблюдений доступен через экспериментальные функции.

### Requirement: Применение настроек при изменении

Настройки приложения и графа ДОЛЖНЫ применяться при изменении. Выбор применяет значение сразу, для текстового поля завершением ввода служит уход из поля или Enter. Незавершённые и недействительные значения не заменяют рабочую настройку. Ошибка записи видна рядом с настройкой.

#### Scenario: Изменение графа во время записи

- ДАНО инженер изменил роль в профиле
- КОГДА он выбирает другую модель до завершения запроса
- ТО после повторного открытия видны оба изменения. Создание профиля требует явного действия инженера.

### Requirement: Расход на отдельное обращение

Карточка ДОЛЖНА показывать перед журналом исполнителей статистику запусков этого обращения. Входные и выходные токены различаются, стоимость указывается только по имеющимся данным.

#### Scenario: Повторный запуск с неполными измерениями

- ДАНО у обращения несколько разборов, часть измерений отсутствует
- КОГДА инженер открывает журнал
- ТО видны границы учтённого расхода, нулевые значения отличаются от неизвестных.

### Requirement: Выбор профиля перед запуском

Новый проект ДОЛЖЕН открываться без созданного системой профиля. Создавать обращения и прикладывать журналы можно до настройки графа. Для первого и повторного разбора инженер ДОЛЖЕН явно выбрать сохранённый профиль проекта. При пустом списке рядом с запуском доступен переход к созданию профиля.

#### Scenario: Первый и последний профиль

- ДАНО проект без профилей
- КОГДА инженер создаёт и сохраняет первый профиль в графе
- ТО он становится доступен для выбора в обращении. После удаления последнего профиля история сохраняется, для следующего запуска снова нужна настройка.
