# Предложение: агентный MVP обработки обращений (консультативный режим)

## Зачем это изменение

Это фаза 2 согласованного роадмапа. Слой знаний (импорт, индексация, гибридный поиск, оценка) работает и измерим; следующим шагом продукт обязан показать главную ценность — **обработку обращения пользователя от текста до результата**. Без тикетного конвейера Issues-раздел продукта остаётся заглушкой, а киллер-метрики (процент автоварешений, $/тикет) нечем считать.

MVP сознательно консервативен: **консультативный режим** — система отвечает обоснованным ответом с цитатами или эскалирует с досье. Патчи, песочница и Merge Request — фаза 4; анализ логов/скриншотов — позже; генерация кода не выполняется.

## Текущее состояние → желаемое

- Сейчас: Issues-страница — заглушка «скоро»; тикетов нет; поиск не потребляется агентами.
- Желаемое: обращения создаются и хранятся; конвейер `Триаж → Исследователь → Решатель` выполняется по кнопке; каждый шаг пишет в append-only трассировку; ответ содержит цитаты только из найденного контекста либо эскалацию с досье; для проекта выбирается chat-модель конвейера.

## Что НЕ входит

- LangGraph-зависимость: граф MVP детерминирован и реализуется чистым Python-оркестратором (решение и мотивы — в design.md); миграция на LangGraph — отдельное будущее изменение, если понадобится ветвление сложнее.
- Fix Writer, песочница, GitLab MR, анализ вложений — фазы 4+.
- Асинхронный запуск через Celery — MVP выполняется синхронно с таймаутом (как генерация материалов); фоновый режим — позже.
- Cost-routing (маленькая/большая модель по сложности) — фаза 3; MVP использует одну chat-модель конвейера.
