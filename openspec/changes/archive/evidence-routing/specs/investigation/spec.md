## MODIFIED Requirements

### Requirement: Локальная проверка основания

Система ДОЛЖНА начать с доступных журналов обращения, учитывать соответствие пользовательскому сценарию, проверить документацию по реализации, учитывать подходящие случаи из истории этого проекта и сохранять происхождение данных в журнале.

#### Scenario: В документации описано отсутствующее поведение

- ДАНО документация обещает функцию и в исходниках подтверждения нет
- КОГДА автор предлагает ответ только из документации
- ТО система не выдаёт его как подтверждённый результат.

#### Scenario: Контракт описывает HTTP-маршрут без регистрации

- ДАНО контракт описывает HTTP-метод и путь, а в собранных исходниках есть только чтение данных
- КОГДА автор предлагает ответ с этим маршрутом
- ТО система перепроверяет точный путь в локальных исходниках и конфигурации
- И ЕСЛИ регистрация метода и пути не найдена, система запрашивает соответствующий файл и не утверждает, что маршрут работает.

#### Scenario: Журнал содержит версию сервиса

- ДАНО журнал текущего обращения содержит сведения о фактической версии и платформе
- КОГДА включён специалист по журналам
- ТО эти наблюдения со ссылками доступны аналитику перед формированием поисковых запросов.

#### Scenario: Для HTTP-маршрута найдена только реализация выборки

- ДАНО документация указывает метод и путь, в найденном коде есть только выборка записей из базы
- КОГДА система проверяет вывод
- ТО она ищет в исходниках регистрацию маршрута. Подтверждение требует связи метода и пути в исполняемом коде или конфигурации маршрутизатора. Декларация OpenAPI, пример HTTP-запроса и метод репозитория сами по себе такой связи не устанавливают.

### Requirement: Ограниченный повторный маршрут

Система ДОЛЖНА после неподтверждённого локального вывода при возможности выполнить один разрешённый внешний поиск и локальную перепроверку. Профиль и разрешение проекта определяют доступность инструментов.

#### Scenario: Причину не удалось подтвердить

- ДАНО локальных сведений недостаточно, внешний поиск разрешён и настроен
- КОГДА анализ либо проверка выявляет пробел
- ТО система проверяет доступный внешний сигнал, сопоставляет его с локальными материалами и только затем запрашивает недостающие сведения.
