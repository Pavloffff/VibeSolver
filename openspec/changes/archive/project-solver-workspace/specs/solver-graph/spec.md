# Граф Solver

## ADDED Requirements

### Requirement: Именованные профили проекта

Система ДОЛЖНА хранить профили Solver в пределах проекта. Пользователь ДОЛЖЕН иметь возможность создать, переименовать, изменить и удалить профиль, а также назначить профиль по умолчанию. Профиль содержит параметры включения этапов и назначения моделей Solver. При удалении профиля по умолчанию пользователь ДОЛЖЕН выбрать замену в той же операции. Назначение по умолчанию ДОЛЖНО ссылаться на существующий профиль проекта.

#### Scenario: Однократный выбор профиля

- **ДАНО** в проекте есть профиль по умолчанию и другой доступный профиль
- **КОГДА** пользователь выбирает другой профиль для одного запуска
- **ТОГДА** запрос выполняется с выбранным профилем, а запуск без явного выбора использует профиль по умолчанию

#### Scenario: Недоступный профиль

- **ДАНО** в запросе указан удалённый профиль или профиль другого проекта
- **КОГДА** пользователь запускает Solver
- **ТОГДА** система отклоняет запрос с понятной ошибкой, сохраняя прежнее состояние обращения

### Requirement: Настройки этапов и маршрутов

Граф ДОЛЖЕН применять параметры профиля к запуску. Когда триаж включён, он формирует поисковые запросы и определяет сложность. При выключенном триаже граф ДОЛЖЕН использовать заголовок и описание обращения как прямой запрос к внутреннему поиску и выбирать основную модель, если этап решения включён. При включённом триаже бюджетная модель применяется к простым обращениям при наличии назначения. Основная модель используется во всех остальных случаях. Выключенный этап ДОЛЖЕН быть отмечен в истории запуска с причиной пропуска.

Поиск материалов в пределах проекта и доступных логов обращения, а также проверка ссылок ДОЛЖНЫ оставаться обязательными частями графа. Ответ пользователю ДОЛЖЕН опираться на проверяемые ссылки из досье текущего запуска. При пустом досье, отсутствии валидных ссылок в предложенном ответе или решении модели об эскалации граф ДОЛЖЕН направить обращение инженеру. При выключенном этапе решения граф ДОЛЖЕН передать инженеру досье с найденными материалами и причиной эскалации. При пустом досье причина ДОЛЖНА указывать на отсутствие подходящих материалов.

#### Scenario: Триаж выключен

- **ДАНО** у профиля выключен триаж и включено решение, назначены основная и бюджетная модели
- **КОГДА** пользователь запускает Solver и поиск возвращает материалы
- **ТОГДА** граф использует прямой запрос к внутреннему поиску, передаёт материалы основной модели и проверяет ссылки ответа

#### Scenario: Решение выключено

- **ДАНО** у профиля выключено решение и поиск возвращает материалы
- **КОГДА** выполняется граф
- **ТОГДА** система передаёт досье инженеру со статусом эскалации и отмечает этап решения как пропущенный

### Requirement: Совместимость с текущими настройками проектов

При переходе на профили система ДОЛЖНА создать для существующего проекта профиль по умолчанию с текущими назначениями моделей Solver и настройками, воспроизводящими прежний граф. Назначения моделей для индексации и генерации документации ДОЛЖНЫ продолжать действовать в пределах проекта. Система ДОЛЖНА проверять доступность и пригодность моделей для активных ролей. При включённых триаже и решении без отдельного назначения для триажа ДОЛЖНА применяться основная модель. Если включён только триаж, он также может использовать основную модель как резервную. Выключенные этапы могут хранить назначения для последующего включения.

#### Scenario: Запуск после обновления

- **ДАНО** у существующего проекта назначены основная и бюджетная модели Solver
- **КОГДА** пользователь запускает разбор без явного выбора профиля после обновления
- **ТОГДА** профиль по умолчанию использует сохранённые назначения и прежние правила выбора модели

### Requirement: Снимок профиля и история запусков

Система ДОЛЖНА атомарно фиксировать начало запуска и снимок его конфигурации, включая профиль, его имя, параметры этапов и назначения моделей. Граф ДОЛЖЕН использовать этот снимок до завершения запуска. Снимок и история ДОЛЖНЫ сохраняться после переименования, изменения или удаления профиля. Каждому запуску ДОЛЖЕН соответствовать отдельный идентификатор. Шаги ДОЛЖНЫ добавляться в историю своего запуска с фактическим состоянием этапа и при наличии с использованной моделью, длительностью, токенами и стоимостью. Система ДОЛЖНА сохранять итог запуска, включая ошибку, и показывать прежние записи истории обращения, даже если для них отсутствуют снимки профилей и идентификаторы запусков.

Снимок ДОЛЖЕН сохранять назначения профиля отдельно от моделей, определённых для включённых этапов. История ДОЛЖНА показывать определённые модели, в том числе основную модель в роли триажа при наследовании. Шаги уточняют фактические вызовы, включая условный выбор бюджетной модели. Для выключенных ролей история ДОЛЖНА оставлять поле модели пустым. Завершающий шаг ДОЛЖЕН сохранять пути и строки всех материалов досье, а также отмечать ссылки, использованные в ответе или переданные инженеру.

#### Scenario: Профиль изменён во время запуска

- **ДАНО** запуск начался с сохранённым снимком профиля
- **КОГДА** пользователь меняет модель в профиле и повторно запускает обращение после завершения первого запуска
- **ТОГДА** первый запуск использует исходные настройки, второй получает новые настройки, а шаги и результаты доступны отдельно для каждого запуска

#### Scenario: Открытие истории, созданной до обновления

- **ДАНО** в обращении сохранились записи шагов прежнего графа
- **КОГДА** пользователь открывает историю после обновления
- **ТОГДА** прежние записи доступны отдельно от новых запусков с подтверждёнными границами
