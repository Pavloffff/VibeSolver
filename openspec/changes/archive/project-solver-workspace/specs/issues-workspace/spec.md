## ADDED Requirements

### Requirement: Рабочее пространство обращений проекта

СИСТЕМА ДОЛЖНА предоставлять в выбранном проекте отдельный раздел решения обращений, доступный через навигацию проекта рядом с обзором и источниками знаний. Переход между разделами ДОЛЖЕН сохранять контекст выбранного проекта. СИСТЕМА ДОЛЖНА объяснять недоступность запуска при незавершённой подготовке индексов и не позволять запуск до их готовности.

#### Scenario: Переход к обращениям и обратно

- ДАНО пользователь открыл проект
- КОГДА пользователь выбирает раздел обращений и возвращается к источникам знаний
- ТО система показывает соответствующий раздел того же проекта

#### Scenario: Индексы не готовы

- ДАНО индексы проекта не готовы
- КОГДА пользователь открывает раздел обращений
- ТО система объясняет, что необходимо завершить подготовку индексов, и не разрешает запуск решения

### Requirement: Очередь и детали обращения

СИСТЕМА ДОЛЖНА показывать очередь обращений выбранного проекта и позволять выбрать обращение для просмотра деталей. В деталях ДОЛЖНЫ быть доступны описание, статус, результат или причина эскалации, ссылки на использованные источники, вложения логов и история выполнения при наличии. Создание обращения, импорт из TXT и запуск или повторный запуск ДОЛЖНЫ оставаться доступными; существующие ограничения готовности вложений ДОЛЖНЫ соблюдаться.

#### Scenario: Выбор обращения

- ДАНО в проекте есть несколько обращений
- КОГДА пользователь выбирает обращение в очереди
- ТО система показывает детали именно этого обращения и сохраняет возможность выбрать другое

#### Scenario: Пустая очередь

- ДАНО в проекте нет обращений
- КОГДА пользователь открывает раздел обращений
- ТО система показывает понятное пустое состояние и способ добавить обращение

### Requirement: Профиль решения для запуска

СИСТЕМА ДОЛЖНА использовать профиль решения проекта по умолчанию и позволять выбрать доступный профиль для отдельного запуска. Выбор для отдельного запуска НЕ ДОЛЖЕН изменять профиль проекта по умолчанию. Перед запуском пользователь ДОЛЖЕН видеть выбранный профиль; недоступный профиль НЕ ДОЛЖЕН приводить к незаметной подмене.

#### Scenario: Запуск с переопределением

- ДАНО у проекта задан профиль по умолчанию
- КОГДА пользователь выбирает другой доступный профиль для запуска обращения
- ТО запуск использует выбранный профиль, а профиль проекта по умолчанию остаётся прежним

#### Scenario: Запуск без переопределения

- ДАНО у проекта задан доступный профиль по умолчанию
- КОГДА пользователь запускает обращение без выбора другого профиля
- ТО запуск использует профиль проекта по умолчанию

### Requirement: Понятный журнал выполнения

СИСТЕМА ДОЛЖНА отображать шаги запуска в порядке выполнения и для каждого показывать доступные сведения о модели, результате, входных данных, использованных источниках и ошибке. Если доступны длительность, токены и стоимость, система ДОЛЖНА показывать и их. Детали ДОЛЖНЫ быть раскрываемыми; техническое представление сохранённых данных МОЖЕТ дополнять понятное представление. Секреты и учётные данные НЕ ДОЛЖНЫ отображаться.

#### Scenario: Просмотр выполненного шага

- ДАНО запуск сохранил сведения о модели, входных данных, источниках и результате шага
- КОГДА пользователь раскрывает шаг журнала
- ТО система показывает сохранённые сведения и доступные показатели выполнения

#### Scenario: Ошибка шага

- ДАНО шаг завершился с сохранённой ошибкой
- КОГДА пользователь просматривает журнал
- ТО система показывает ошибку в контексте соответствующего шага

#### Scenario: Исторический запуск с неполными данными

- ДАНО историческая запись не содержит часть полей журнала
- КОГДА пользователь открывает её
- ТО система показывает имеющиеся данные и обозначает отсутствующие сведения как недоступные без выдумывания значений

### Requirement: Доступность и локализация рабочего пространства

СИСТЕМА ДОЛЖНА локализовать пользовательские строки раздела обращений и журнала на английский, русский и китайский через словари переводов. Очередь, выбор обращения, навигация, формы и раскрывающиеся детали ДОЛЖНЫ работать с клавиатуры и иметь видимый фокус и доступные названия. Интерфейс ДОЛЖЕН адаптироваться к узкому экрану без потери доступа к очереди или деталям.

#### Scenario: Работа на узком экране с клавиатурой

- ДАНО пользователь открыл раздел на узком экране и пользуется клавиатурой
- КОГДА пользователь выбирает обращение и раскрывает шаг журнала
- ТО элементы доступны последовательно с видимым фокусом, а очередь и детали остаются доступными

#### Scenario: Изменение языка

- ДАНО пользователь выбрал поддерживаемый язык
- КОГДА пользователь открывает раздел обращений и журнал
- ТО система показывает интерфейсные подписи и состояния на выбранном языке
