## ADDED Requirements

### Requirement: Импорт обращения из TXT

Система ДОЛЖНА позволять пользователю выбрать UTF-8 текстовый файл `.txt` в форме создания обращения проекта. Первая непустая строка файла ДОЛЖНА заполнить поле заголовка, а текст после этой строки ДОЛЖЕН заполнить поле описания. После импорта оба поля ДОЛЖНЫ оставаться редактируемыми; файл сам по себе НЕ ДОЛЖЕН создавать обращение.

#### Scenario: Импорт корректного файла

- ДАНО: файл `.txt` содержит заголовок в первой непустой строке и описание в последующих строках
- КОГДА: пользователь выбирает файл
- ТОГДА: заголовок и описание появляются в соответствующих полях формы
- И: пользователь может изменить их и отправить обращение обычной кнопкой формы

#### Scenario: Переводы строк и пустые строки перед заголовком

- ДАНО: файл содержит пустые строки перед заголовком и использует CRLF-переводы строк
- КОГДА: пользователь выбирает файл
- ТОГДА: первая непустая строка становится заголовком, а последующие строки — описанием

#### Scenario: Пустой файл

- ДАНО: файл не содержит непустой строки
- КОГДА: пользователь выбирает файл
- ТОГДА: система показывает локализованную ошибку импорта и не отправляет обращение

#### Scenario: Нет описания после заголовка

- ДАНО: файл содержит заголовок, но не содержит описания, достаточного для существующей валидации формы
- КОГДА: пользователь выбирает файл
- ТОГДА: система показывает локализованную ошибку импорта и не отправляет обращение

#### Scenario: Файл другого типа

- ДАНО: пользователь выбирает файл с расширением, отличным от `.txt`
- КОГДА: файл выбирается в поле импорта
- ТОГДА: выбор ограничен `.txt`, а неподдерживаемый файл не загружает и не изменяет поля обращения

#### Scenario: Ошибка чтения файла

- ДАНО: браузер не смог прочитать выбранный `.txt`-файл
- КОГДА: чтение завершается ошибкой
- ТОГДА: система показывает локализованную ошибку и позволяет пользователю выбрать файл повторно

#### Scenario: Изменение импортированного обращения

- ДАНО: корректный файл импортирован в форму
- КОГДА: пользователь изменяет заголовок или описание и отправляет форму
- ТОГДА: система создаёт обращение с отредактированными значениями через существующий endpoint
