# Техническое решение

## Хранение

Сохранить текущую модель ресурсов в `sources.config.resources`. Каждому новому ресурсу назначать стабильный `id`; `type` указывает `archive` или `markdown`, `name` хранит имя файла, а `config.upload_key` — ссылку на объект в S3. Дополнительная метаинформация (например, происхождение `uploaded` или `generated`) остаётся расширяемой.

Текст Markdown читать и обновлять через source-scoped API. Usecase проверяет наличие ресурса и его тип перед обращением к S3. Архивы остаются непрозрачными вложениями; обновление архива загружает новый объект и меняет ссылку в конфигурации.

## Интерфейс

- Для каждой категории доступны добавление `.zip`/`.tar.gz` или `.md`.
- Markdown открывается в модальном редакторе с режимами просмотра и редактирования, сохранением и merge с другим Markdown-материалом.
- Merge добавляет выбранный текст к открытому материалу через Markdown-разделитель; пользователь проверяет результат до сохранения.
- Действия генерации User Flow из документации и документации из кода используют registry интерфейса. Пока генератор не зарегистрирован, UI показывает локализованное уведомление и не создаёт фиктивный файл.
- Будущая генерация документации добавляет отдельный материал и никогда не перезаписывает/не удаляет основную документацию; удаление выполняется только явным действием пользователя.
- Удаление материала подтверждается пользователем, затем удаляет metadata проекта и объект в S3.
- Весь пользовательский текст выводится как текст/Markdown-превью без исполнения HTML.
