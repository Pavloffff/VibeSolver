# Предложение: отдельные индексы кода, документации и User Flow

## Проблема

Сейчас импорт репозитория сохраняет сведения о файлах, но для Git по умолчанию записывает в SeaweedFS только манифест, а содержимое остаётся доступно лишь во время временного клонирования. Реальная индексация отсутствует: на странице проекта есть одна заглушка с выбором embedding-модели. Код, документация и User Flow не имеют независимых статусов и не участвуют в проверке готовности проекта. Кнопка перехода к обращениям доступна до построения контекста.

## Решение

Ввести три независимых, версионируемых процесса индексации:

1. **Код** — после импорта создать постоянный снимок исходных файлов в SeaweedFS, разбить исходный код по синтаксическим узлам tree-sitter и подготовить лексический и векторный поиск.
2. **Документация** — индексировать постоянные файлы проекта отдельным конвейером разбора документов; Markdown разбивать по структуре заголовков, прочие поддерживаемые форматы — соответствующими адаптерами.
3. **User Flow** — валидировать сценарии как структурированные данные, хранить версии и отдельно строить векторное и лексическое представление для поиска сценариев.

У каждого индекса собственные запуск, статус, прогресс, ошибка и версия входного снимка. Генерация документации из кода доступна только после завершённой индексации кода; генерация User Flow — только после завершённой индексации документации. Проект считается готовым, когда завершён импорт кода и актуальны все три индекса. До этого индикатор готовности горит красным, а переход к Issues заблокирован. Возле User Flow интерфейс объясняет, что сценарий описывает действия пользователя, ожидаемый результат, связанные компоненты и возможные сбои.

## Хранение исходных файлов

SeaweedFS/S3 становится постоянным хранилищем байтов файлов и снимков источников. PostgreSQL хранит метаданные, версии источников, статусы заданий, фрагменты, поисковые поля, векторы и ссылки на S3-объекты, но не большие тела файлов. Импорт Git должен сохранять содержимое каждого файла, а не только манифест. Ручные локальные материалы уже загружаются в S3; их объектные ключи должны войти в единый каталог версий. Будущие Confluence/Wiki-адаптеры обязаны сохранять полученные страницы и вложения как версионированный снимок перед индексацией.

## Ограничения

- Изменение проектирует и реализует жизненный цикл исходных снимков и трёх индексов; обучение собственных embedding-моделей не входит в объём.
- Tree-sitter — специализированный разбор кода; он не заменяет парсер документации и не применяется к произвольному тексту.
- Текущая Confluence-кнопка-заглушка не является импортированным источником и не может сделать индекс документации готовым.
- Issues остаются заблокированы, пока любой обязательный индекс отсутствует, упал или относится к устаревшей версии исходных данных.
