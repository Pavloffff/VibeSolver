# VibeSolver

Мультиагентная система анализа и обработки обращений в техническую поддержку ИТ-систем с использованием методов генерации с дополненной выборкой (RAG).

Система принимает неструктурированное обращение пользователя и выполняет полный цикл поддержки: триаж по пользовательским сценариям, диагностику по логам и скриншотам, поиск по коду и документации продукта, генерацию исправления с подтверждением человеком и создание Merge Request — либо эскалацию дежурному разработчику с полным досье.

## Проблематика

- Обращения обрабатываются слишком долго: время решения растёт с нагрузкой
- Опыт и знания о продукте распределены между линиями поддержки и не накапливаются
- Общедоступные GPT-модели не знают конкретный продукт: его код, документацию, типовые сценарии
- Нет стандартизированных мультиагентных решений, объединяющих процессы разработки и техподдержки

## Архитектура

Система объединяет два слоя:

- **Слой знаний о продукте** — превращает репозиторий, Confluence, Wiki и пользовательские сценарии (User Flow) в машиночитаемый контекст для LLM: импорт, AST-чанкинг кода (tree-sitter), эмбеддинги (bge-m3), гибридный поиск (dense + BM25 + rerank), сжатие контекста. Работает как внутренний REST-сервис для агентной части.
- **Слой обработки обращений** — жизненный цикл тикета на мультиагентном графе (LangGraph): приём → триаж → анализ логов/скриншотов → исследование кода в скоупе сценария → генерация патча в песочнице → подтверждение человеком → Merge Request или эскалация.

## Стек технологий

- **Клиентская часть**: React, TypeScript
- **Серверная часть**: Python, FastAPI, Celery, Redis
- **Агентная часть**: LangGraph, Pydantic
- **Хранение данных**: PostgreSQL, pgvector, SeaweedFS
- **Обработка контента**: tree-sitter, unstructured
- **Эмбеддинги и переранжирование**: bge-m3, bge-reranker (локально)
- **Изоляция выполнения**: Docker (`--network none`, лимиты CPU/RAM)
- **Интеграции**: GitLab API, Confluence API
- **Языковые модели**: облачные DeepSeek и Z.ai GLM, локальные Qwen, gpt-oss, deepseek — через единый LLM-шлюз, модель подбирается под каждого агента
- **Наблюдаемость**: Langfuse

## Установка

Чтобы запустить проект локально, выполните следующие шаги:

1. Склонируйте репозиторий:

```
git clone git@github.com:Pavloffff/VibeSolver.git
```

2. Перейдите в директорию проекта:

```
cd VibeSolver
```

3. Создайте файл конфигурации окружения:

```
cp .env.example .env
```

4. Запустите инфраструктуру и сервисы через Docker Compose:

```
docker compose up -d
```

## Запуск

Два способа пользования системой: **веб-интерфейс** (браузер) и **десктоп-приложение** (Electron). Интерфейс один и тот же, выбор за вами.

### Веб-интерфейс (Docker)

После `docker compose up -d` (см. «Установка») поднимаются все сервисы:

| Сервис | Адрес | Назначение |
|---|---|---|
| Веб-интерфейс | http://localhost:8080 | основной UI |
| API | http://localhost:8000 | REST API, документация Swagger: `/docs` |
| S3 (SeaweedFS) | http://localhost:8333 | файловое хранилище (raw-файлы репозиториев) |
| PostgreSQL | localhost:5432 | база данных (пользователь/пароль из `.env`) |
| Redis | localhost:6379 | очередь задач импорта |

Откройте http://localhost:8080 в браузере. При первом входе выберите режим: «Локально» (инфраструктура уже должна быть поднята) или «На сервер» (укажите адрес API удалённого сервера и нажмите «Проверить соединение»). Язык интерфейса переключается в «Настройках» (English / Русский / 中文, по умолчанию English).

Остановить всё:

```
docker compose down
```

### Десктоп-приложение (Windows / Linux / macOS)

Сначала соберите установщик для вашей ОС (см. «Сборка»), затем запустите файл из `build/dist`:

- Windows: `VibeSolver-Setup-<версия>.exe`
- Linux: `VibeSolver-<версия>.AppImage`
- macOS: `VibeSolver-<версия>.dmg`

При первом запуске приложение покажет экран настройки:

1. Выберите язык интерфейса.
2. Выберите режим:
   - **«Локально»** — приложение само поднимет инфраструктуру в фоне (`docker compose up -d` из корня репозитория) и дождётся готовности сервера. Требуется установленный и запущенный Docker; без него приложение покажет подсказку со ссылкой на установку. Нужны файлы `compose.yml` и `.env` из корня репозитория (при упакованной установке путь можно задать переменной `VIBESOLVER_REPO_ROOT`).
   - **«Подключиться к серверу»** — введите адрес API (например, `http://192.168.1.10:8000`) и проверьте соединение. Локальная инфраструктура не поднимается.
3. Нажмите «Начать работу».

Настройки (режим, адрес, язык) можно изменить позже: вкладка «Настройки» в приложении. Все параметры хранятся в конфиге приложения, в установщик ничего не «запекается».

## Сборка

Для сборки десктоп-приложения под вашу операционную систему выполните соответствующий скрипт в корне репозитория. Локальный режим упакованного приложения требует файлы `compose.yml` и `.env` из корня репозитория (см. `VIBESOLVER_REPO_ROOT`).

**Windows** (PowerShell):

```
.\build-windows.ps1
```

Сборка запускает тесты backend (pytest, ruff, mypy) и frontend (lint, vitest, build) и только затем собирает установщик .exe.

Переменные окружения для разработки (не обязательны, в установщик ничего не «запекается»):

- `VIBESOLVER_LOCAL_API` — адрес локального API для режима «Локально» (по умолчанию `http://localhost:8000`);
- `ELECTRON_DEV_URL` — URL dev-сервера Vite (например, `http://localhost:5173`): десктоп-приложение загрузит его вместо собранного `frontend/web/dist`;
- `VIBESOLVER_REPO_ROOT` — путь к корню репозитория для локального режима в упакованном приложении (по умолчанию ищется вверх по дереву каталогов от места установки по файлу `compose.yml`);
- `VIBESOLVER_HEALTH_TIMEOUT_MS`, `VIBESOLVER_HEALTH_POLL_INTERVAL_MS`, `VIBESOLVER_HEALTH_REQUEST_TIMEOUT_MS` — таймауты ожидания сервера в десктоп-приложении (по умолчанию 180000 / 3000 / 4000 мс).

**Linux**:

```
./build-linux.sh
```

Сборка .AppImage для Linux выполняется только на Linux.

**macOS**:

```
./build-mac.sh
```

Сборка .dmg для macOS должна выполняться на macOS — ограничение electron-builder: кросс-сборка macOS-установщиков из Windows/Linux не поддерживается.

Требования к машине сборки:

- Docker (для инфраструктуры и образа backend)
- Node.js и npm (для frontend)
- Python 3.12+ и uv (для backend)
- Для macOS-сборки: macOS с Xcode Command Line Tools

Скрипт проверяет backend (тесты, линтер, типизация), собирает фронтенд и упаковывает десктоп-приложение (Electron) в исполняемый файл для текущей ОС: `.exe` для Windows, `AppImage` для Linux, `.dmg` для macOS. Готовые артефакты кладутся в `build/dist`.

## Разработка

### Dev-режим (без Docker для backend)

Поднимите только инфраструктуру, а код запускайте локально с автоперезагрузкой:

```
docker compose up -d postgres redis
```

Backend (в отдельном окне, из папки `backend`):

```
uv sync
uv run uvicorn app.api.main:app --reload --port 8000
```

Frontend (из папки `frontend/web`; dev-сервер сам проксирует `/api` на `http://localhost:8000`):

```
npm install
npm run dev
```

Десктоп в dev-режиме (из папки `frontend/desktop`) — грузит dev-сервер Vite вместо собранного бандла:

```
npm install
npm run build
$env:ELECTRON_DEV_URL="http://localhost:5173"
npx electron .
```

### Проверки

Backend (из `backend`):

```
uv run pytest
uv run ruff check .
uv run mypy app
```

Frontend (из `frontend/web`):

```
npm run lint
npm run test
npm run build
```

Десктоп (из `frontend/desktop`):

```
npx tsc -p tsconfig.json --noEmit
```

### Структура и спецификации

```
backend/           # Python: API (FastAPI), коннекторы источников, воркеры (Celery), миграции (goose)
frontend/web/      # React + TypeScript (веб-версия)
frontend/desktop/  # Electron-обёртка над тем же UI
build/             # общие скрипты сборки
openspec/          # спецификации: proposal → specs → tasks → apply → archive
```

Правила для агентов и стандарты кода — в `AGENTS.md`. Языки интерфейса (en/ru/zh) добавляются файлом-словарём в `frontend/web/src/i18n/`.
