# Рабочее пространство проекта: обращения и Solver

В проекте есть разделы «Обзор» и «Обращения», а также страница «Граф решения». Просмотр «Источников знаний» расположен внутри «Обзора», а не как отдельный раздел навигации проекта. Навигация сохраняет выбранный проект. Решение обращений доступно после завершения обязательной подготовки индексов; пока проект не готов, запуск заблокирован и интерфейс подсказывает, что нужно завершить.

## Обращения

В разделе «Обращения» можно создать обращение вручную или заполнить форму из TXT-файла, просматривать очередь, открывать карточку обращения и запускать решение или повторять запуск. В карточке отображаются описание, статус, ответ либо причина передачи инженеру, ссылки на использованные материалы, вложения логов и журнал запусков. Запуск недоступен, пока вложенные логи обрабатываются или завершились ошибкой.

Перед запуском можно выбрать профиль Solver для этого запуска. Изначально выбран профиль проекта по умолчанию. Выбор другого профиля действует только для запуска обращения и не меняет значение по умолчанию в проекте. Каждый запуск сохраняет собственный снимок профиля и результатов, поэтому последующие изменения профиля не меняют историю.

Журнал показывает запуски отдельно: имя профиля, итоговый статус, время, назначенные модели, шаги и ошибку при наличии. У шага отображаются статус (выполнен, пропущен или завершился ошибкой), модель и доступные метрики — длительность, токены и стоимость. Входные и выходные данные раскрываются отдельно. Для старых записей без части метаданных показываются только сохранённые сведения. Секретоподобные поля исключаются из отображения.

## Профили графа решения

На странице «Граф решения» можно создавать, переименовывать, изменять и удалять профили проекта, а также назначать профиль по умолчанию. При удалении профиля по умолчанию нужно в той же операции указать профиль на замену. Профиль содержит переключатели этапов и назначения моделей. Изменения сохраняются кнопкой сохранения.

Граф задаётся сервером. Пользователь может просматривать шаги и переходы и настраивать предусмотренные этапы. Для включённого этапа назначение модели можно оставить пустым, если оно наследуется от основной модели; доступность и пригодность модели проверяются при запуске. Выключенный этап не требует доступной модели для запуска, но профиль может сохранять назначение для последующего включения:

- **Триаж** формирует поисковые запросы и оценивает сложность. Если он выключен, поиск использует заголовок и описание обращения напрямую.
- **Решение** готовит ответ на основе найденных материалов и проверяемых ссылок. При выключенном этапе система передаёт досье инженеру.
- Для простого обращения при включённых триаже и решении может использоваться назначенная бюджетная модель; в остальных случаях применяется основная модель.
- Поиск материалов, проверка ссылок и передача инженеру при недостатке оснований остаются частью графа независимо от переключателей этапов.

Пропущенный этап фиксируется в журнале со статусом и причиной. При обращении к облачному провайдеру ему отправляется текст обращения; при подготовке ответа также отправляются найденные фрагменты источников. Это происходит только если пользователь выбрал модель такого провайдера в активном профиле. Учётные данные и конфигурация проекта провайдеру не передаются. При обновлении существующего проекта создаётся профиль по умолчанию с прежними назначениями Solver и поведением графа.

## Просмотр исходников

В «Источниках знаний» доступно дерево импортированных исходников и предпросмотр текста только для чтения. Просмотр использует снимок последнего успешного импорта; переходы по папкам, веткам и файлам остаются в рамках выбранного снимка. Сбой нового импорта не удаляет доступ к предыдущему успешному снимку. Для бинарных, неподдерживаемых по кодировке или слишком больших файлов интерфейс объясняет, почему предпросмотр недоступен. Содержимое показывается как текст и не исполняется.
