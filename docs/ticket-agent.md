# Агентный конвейер обращений (MVP)

Конвейер обрабатывает обращение пользователя в три шага и завершается обоснованным ответом либо эскалацией. Реализация — детерминированный оркестратор на Python (`app/usecase/ticket_agent.py`); миграция на LangGraph планируется вместе с циклами Fix Writer (фаза 4).

## Шаги конвейера

| Шаг | Модель | Контракт | Что делает |
|---|---|---|---|
| **Триаж** (`triage`) | chat | `TriageResult` | категория, критичность, русское саммари, 1–5 поисковых запросов, missing_info |
| **Исследование** (`investigate`) | — | досье `S1..Sn` | мультизапросный гибридный поиск (`RetrievalUsecase`), round-robin слияние с дедупом, лимиты чанков/символов |
| **Решение** (`resolve`) | chat | `ResolutionResult` | ответ на русском с `source_refs` ИЛИ решение об эскалации с причиной |

Промпты — в реестрах `TRIAGE_SYSTEM` / `RESOLVER_SYSTEM`; выходы валидируются Pydantic strict (`extra="forbid"`) с одним repair-повтором при невалидном JSON.

## Детерминированная маршрутизация

- Решатель выбрал `escalate` → статус `escalated` (причина + досье).
- Решатель выбрал `answer`, но нет валидных ссылок на выданный контекст → принудительная эскалация «модель не сослалась на фрагменты».
- **Пустое досье → эскалация без вызова Решателя** (экономия токенов: не платим за заведомо неотвечаемый запрос).
- Поиск недоступен (нет завершённых индексов / embedding-модели) → эскалация, не ошибка сервера.
- Итераций — один проход; повтор — только новым запуском (`POST /tickets/{id}/run`, запрещён при статусе `running`).

## Трассировка и данные

Каждый шаг пишется в `ticket_steps` (append-only: вход, выход, модель, длительность) — это база для метрик фазы 3 (процент автоварешений, $/тикет по числу и стоимости вызовов LLM). Результат тикета: `tickets.answer`, `citations` (source_ref + path + строки), `escalate_reason`, `triage`.

## Модель конвейера

Роль `ticket_resolution` (требуется capability `chat`) — выбирается в UI раздела «Обращения» или через `PUT /api/v1/models/projects/{id}/selections/ticket_resolution`. Отсутствие/неготовность модели → 422 до выполнения шагов, статус тикета возвращается к прежнему.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `VIBESOLVER_TICKET_AGENT_TIMEOUT_SECONDS` | 180 | таймаут LLM-вызова шага |
| `VIBESOLVER_TICKET_AGENT_MAX_OUTPUT_TOKENS` | 8192 | лимит выхода LLM |
| `VIBESOLVER_TICKET_CONTEXT_CHUNKS` | 12 | максимум чанков в досье |
| `VIBESOLVER_TICKET_MAX_CONTEXT_CHARACTERS` | 24000 | лимит символов досье |

## API

- `POST /api/v1/sources/{id}/tickets` — создать обращение (201)
- `GET /api/v1/sources/{id}/tickets` — список (кратко)
- `GET /api/v1/tickets/{id}` — детали + трассировка
- `POST /api/v1/tickets/{id}/run` — синхронный запуск (404/409/422/502)

Фаза 3 (cost-routing) надстроится поверх этой же трассировки: уровни моделей на шаг и confidence-эскалация.
