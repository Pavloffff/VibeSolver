# Агентный конвейер обращений (MVP)

Конвейер обрабатывает обращение пользователя в три шага и завершается обоснованным ответом либо эскалацией. Реализация — детерминированный оркестратор на Python (`app/usecase/ticket_agent.py`); миграция на LangGraph планируется вместе с циклами Fix Writer (фаза 4).

## Шаги конвейера

| Шаг | Модель | Контракт | Что делает |
|---|---|---|---|
| **Триаж** (`triage`) | ticket_triage (или ticket_resolution) | `TriageResult` | категория, критичность, сложность, русское саммари, 1–5 поисковых запросов, missing_info |
| **Исследование** (`investigate`) | — | досье `S1..Sn` | мультизапросный гибридный поиск (`RetrievalUsecase`), round-robin слияние с дедупом, лимиты чанков/символов |
| **Решение** (`resolve`) | ticket_resolution или ticket_resolution_cheap | `ResolutionResult` | ответ на русском с `source_refs` ИЛИ решение об эскалации с причиной |

Промпты — в реестрах `TRIAGE_SYSTEM` / `RESOLVER_SYSTEM`; выходы валидируются Pydantic strict (`extra="forbid"`) с одним repair-повтором при невалидном JSON.

## Детерминированная маршрутизация

- Решатель выбрал `escalate` → статус `escalated` (причина + досье).
- Решатель выбрал `answer`, но нет валидных ссылок на выданный контекст → принудительная эскалация «модель не сослалась на фрагменты».
- **Пустое досье → эскалация без вызова Решателя** (экономия токенов: не платим за заведомо неотвечаемый запрос).
- Поиск недоступен (нет завершённых индексов / embedding-модели) → эскалация, не ошибка сервера.
- Итераций — один проход; повтор — только новым запуском (`POST /tickets/{id}/run`, запрещён при статусе `running`).

## Трассировка и данные

Каждый шаг пишется в `ticket_steps` (append-only: вход, выход, модель, длительность, входные/выходные токены и стоимость USD). Токены складываются для основного и repair-вызова. Стоимость считается, только если модель содержит `metadata.pricing.prompt` и `metadata.pricing.completion` в USD за токен; неизвестная цена остаётся `null`.

## Модель конвейера

В UI раздела «Обращения» доступны три роли с capability `chat`: `ticket_triage`, `ticket_resolution` (сильная модель) и `ticket_resolution_cheap` (недорогая модель). Триаж без выбранной отдельной модели использует сильную модель; недорогая модель необязательна. Тикет сложности `simple` использует дешёвую модель, если она настроена; `standard` и `hard` всегда используют сильную. Сложность оценивается как известная ошибка/вопрос по документации, воспроизводимый баг и подозрение на дефект кода/инфраструктуры или межсистемный кейс соответственно. Запросы выбора моделей доступны через `PUT /api/v1/models/projects/{id}/selections/{role}`. Без выбранной сильной модели запуск возвращает 422 до выполнения шагов.

Панель статистики отображает долю автоварешений среди завершённых тикетов (`answered / (answered + escalated + failed)`), среднюю стоимость завершённого тикета с известной ценой и суммарные входные/выходные токены. Точность стоимости зависит от наличия цены в метаданных выбранной модели.

### Эксперимент: одна модель против каскада

1. Выберите набор примерно из 10 одинаковых обращений и сохраните их заголовки и описания.
2. Для конфигурации A назначьте одну модель на триаж и решение, оставив дешёвую модель пустой. Запустите все обращения и сохраните ответ `GET /api/v1/sources/{id}/tickets/stats`.
3. Для конфигурации B выберите отдельную недорогую модель триажа и недорогую модель решения; сильную модель оставьте в `ticket_resolution`. Повторно запустите тот же набор и сохраните статистику.
4. Сравните долю автоварешений, среднюю стоимость и токены; отдельно проверьте качество ответов и ссылки на источники. Записывайте цены моделей и конфигурации вместе с результатом, чтобы сравнение можно было повторить.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `VIBESOLVER_TICKET_AGENT_TIMEOUT_SECONDS` | 180 | таймаут LLM-вызова шага |
| `VIBESOLVER_TICKET_AGENT_MAX_OUTPUT_TOKENS` | 8192 | лимит выхода LLM |
| `VIBESOLVER_TICKET_CONTEXT_CHUNKS` | 12 | максимум чанков в досье |
| `VIBESOLVER_TICKET_MAX_CONTEXT_CHARACTERS` | 24000 | лимит символов досье |

## API

- `POST /api/v1/sources/{id}/tickets` — создать обращение (201)
- `GET /api/v1/sources/{id}/tickets` — список (кратко)
- `GET /api/v1/tickets/{id}` — детали + трассировка
- `POST /api/v1/tickets/{id}/run` — синхронный запуск (404/409/422/502)

- `GET /api/v1/sources/{id}/tickets/stats` — агрегаты статусов, стоимости и токенов.
